# 11｜数据属性与模型调用限制测试报告

## 1. 测试结论

**结论：部分通过，当前状态为安全失败。**

系统能够识别三类合法数据属性，拒绝非法枚举；`mock`仅允许模拟数据，授权脱敏或企业真实敏感数据均不会被伪造成模型结果；未配置的真实模型适配器会被拒绝，当前没有发生外部模型调用。主要缺口是创建资料包时可以省略数据属性并自动落为“模拟数据”，不符合“必须主动选择”的方案要求；另外真实模型策略尚未实现，暂时只能阻断，不能验证完整的本地／企业内网调用矩阵。

## 4. 运行证据

- `data_scope_required`：省略属性仍HTTP 201，自动分配“模拟数据”
- `invalid_data_scope_rejected`：HTTP 422
- `non_simulated_mock_blocked`：
  - 授权脱敏数据：HTTP 422
  - 企业真实敏感数据：HTTP 422
- `unconfigured_adapter_blocked`：HTTP 422
- `bootstrap_path_and_secret_scan`：未发现绝对路径或密钥标记
- `api_security_surface`：
  - IdentityVault接口不存在
  - 当前无导出接口
  - 当前无删除接口
- 正常证据响应不包含`relative_path`

## 5. 缺陷与待办

### CORE-11-01｜数据属性不是创建资料包的显式必填输入

- 严重度：高
- 影响：用户忘记选择时，真实资料可能被错误标成模拟数据，进而进入允许范围更宽的模型路径。
- 建议：
  1. 后端移除`data_scope`默认值，缺失时返回HTTP 422。
  2. 前端不预选任何属性，要求用户主动确认。
  3. “企业真实敏感数据”增加二次确认提示。
  4. 数据属性一旦有文件或分析运行，不允许直接修改；如需修改必须审计并重新预检。

### CORE-11-02｜真实模型策略尚未实现

- 类型：待办，不是当前外泄缺陷
- 当前状态：只有`mock`可运行，其他适配器均安全拒绝。
- 待实现：
  1. 为模型适配器增加来源分类：本地、企业内网、经批准公共服务。
  2. 由服务端依据数据属性和适配器分类执行策略，不能由前端决定。
  3. 保存模型名称、版本、量化方式、服务来源、提示词版本、调用时间和结果状态。
  4. 加入“授权脱敏→企业内部服务允许”“真实敏感→公共服务拒绝”等策略矩阵测试。

## 6. 范围说明

- 当前没有真实模型适配器，因此本报告能证明“不会误调用”，不能证明真实本地／企业内网模型已可用。
- 导出为P1候选，当前OpenAPI没有导出端点；本轮不把“未实现导出限制”判为P0缺陷。
- 删除与自动保存期限尚未形成API闭环，应在后续安全专项测试中单独验证。
