# 02－会议资料包创建与编辑测试报告

## 1. 测试结论

**结论：部分实现。**

资料包的创建、详情查看、列表检索、客户／状态／关键字筛选、标题／日期／备注／保存期限／PDF例外原因编辑，以及版本冲突保护均已实现。

但创建后不能编辑客户、资料属性和参会人；API会静默忽略这些未声明字段并仍然递增版本。创建时不传资料属性会自动默认为“模拟数据”，未满足《05方案》“必须由用户选择”的要求。

## 2. 《05方案》需求映射

- 3.1第1、2、15项：创建、编辑、查看资料包；参会信息；数据属性。
- 4.1：会议资料包的日期、客户、材料、参会人、说明和标签。
- 4.5：每个资料包必须选择数据属性。
- 10.2：资料包关键字段。
- 11.1：资料包状态。
- 11.4、13.2：更新接口携带版本号，避免旧页面覆盖。
- 12.1：创建、筛选和查看资料包。

## 3. 测试环境与前置条件

- 使用临时SQLite和临时项目文件目录，自动灌入模拟基础数据。
- 使用FastAPI TestClient，不访问演示数据库写接口。
- 已存在项目 `project-mnt`，客户A～E及采购／开发／PM／产品／品质职能。

## 5. 证据摘要

隔离API探针关键响应：

```text
POST /api/meeting-packages                      201 草稿
GET  /api/meeting-packages/{id}                 200 attendees=2
PATCH /api/meeting-packages/{id} version=1      200 version=2
PATCH /api/meeting-packages/{id} version=1      409
PATCH 未声明字段 version=2                      200 version=3，但字段未改变
POST 省略data_scope                             201 data_scope=模拟数据
非法项目／客户／职能                            404／404／404
非法属性／期限                                  422／422
```

现有自动化回归中的“创建→上传→分析→身份确认→意向确认”闭环也通过：

```text
server\.venv\Scripts\python.exe -m pytest -q

```

## 6. 缺陷与建议

| 缺陷ID | 严重度 | 缺陷 | 建议 |
| --- | --- | --- | --- |
| BE-CORE-005 | 高 | 资料包编辑不覆盖客户、资料属性和参会人 | 增加带版本号的资料包核心字段编辑及参会人增删改接口；资料属性变更要重新触发安全策略与预检 |
| BE-CORE-006 | 中 | Pydantic默认静默忽略未知字段，且无实际变更也递增版本 | 更新请求配置 `extra="forbid"`；没有有效变更时返回422或保持版本不变 |
| BE-CORE-007 | 中 | `data_scope`缺省为模拟数据，未强制用户选择 | 从创建模型移除默认值；前端和API都要求显式提交三选一 |
| BE-CORE-008 | 中 | 参会人确认信息只能在创建时写入 | 为参会人提供资源化接口，保存人工确认状态、版本和操作者 |
