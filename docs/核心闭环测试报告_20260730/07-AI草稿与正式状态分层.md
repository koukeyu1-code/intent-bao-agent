# 07｜AI草稿与正式状态分层测试报告

## 1. 测试结论

**结论：部分通过。**

运行验证确认：模拟分析只生成待确认观察，不会直接生成正式状态；说话人未确认时无法发布；人工确认后看板才新增正式结果；强制重分析不会覆盖已确认历史。主要缺口是人工修改和确认会直接改写原始观察中的`AI建议态度／采用阶段`字段，无法从当前观察记录直接还原“AI最初输出”。

## 3. 前置条件

在独立临时数据库中创建一个模拟会议资料包，上传人工纪要并运行`mock`分析。分析产生3条观察及3个待确认说话人。

## 6. 缺陷与修改建议

### CORE-07-01｜AI原始建议会被人工修订覆盖

- 严重度：中
- 当前表现：
  - 人工整理接口直接更新`RawIntentObservation.suggested_attitude`等字段。
  - 正式确认接口也把最终态度和采用阶段写回同一组“suggested”字段。
  - 虽有确认记录，但当前观察对象不再代表模型原始输出。
- 影响：
  - 无法直接比较“AI最初建议、人工修改、最终正式结论”。
  - 后续计算模型准确率和人工修正率时缺少稳定基线。
- 建议：
  1. 将`ai_suggested_*`设为分析运行产生后不可变。
  2. 新增`reviewed_*`或“人工整理版本”保存确认前调整。
  3. 正式状态只读取人工确认提交值，不回写AI原始字段。
  4. 每次重分析生成新的观察版本并明确关联AnalysisRun。

## 7. 边界说明

- 当前分层能够防止AI草稿直接进入正式看板，核心发布门禁有效。
- 本报告不评价真实模型准确率；全部模型结果为明确标识的模拟结果。
- 强制重分析会新增一组观察，属于追加而非覆盖；后续界面需清楚区分不同AnalysisRun，避免重复待确认项造成误解。
