# 03－材料上传与预检测试报告

## 1. 测试结论

**结论：部分实现。**

首期声明的扩展名矩阵、材料类型映射、本地保存、哈希去重、重复文件保留新版本、文件名路径清洗、物理路径隐藏，以及“无材料／录音或转写稿缺PDF／录屏免PDF”三类基础规则已实现。

但当前所谓“预检”主要是扩展名和组合规则检查。空文件、伪造PDF、错误MIME均可上传并进入“模拟分析已完成”；没有PDF页数、加密、可读性、音视频时长、120分钟上限等检查，PDF例外也只有一段文字，没有负责人确认记录。因此不能视为《05方案》定义的完整预检。

## 2. 《05方案》需求映射

- 3.1第2、3、15项：多类型上传、格式／大小／完整性／数据属性预检。
- 4.1～4.5：资料包材料、格式矩阵、容量、PDF配套规则和数据属性。
- 6.2第2～3步：文件预检和文档解析。
- 10.2：文件哈希、大小、格式、解析状态。
- 11.4：重复文件哈希识别并允许新版本。
- 12.2：上传、材料类型、配套PDF、预检结果和修复建议。
- 13.1 Material Service：上传、校验、解析、哈希和生命周期。

## 3. 测试环境与数据隔离

- 临时SQLite、临时 `projects/<project>/<package>/source/`。
- 小体积伪材料只用于验证接口规则，不冒充真实解析效果。
- 未执行2GB文件和100页真实PDF压力测试；相应结论来自动态负向测试和代码契约审查。
- 临时目录测试后已删除，演示目录元数据未变化。

## 5. 支持格式动态证据

以下14组均返回201，且类型与预期一致：

```text
audio.mp3 / audio.wav / audio.m4a           → 录音
screen.mp4                                  → 录屏
transcript.txt/.md/.docx/.srt/.vtt          → 转写稿
minutes.txt/.md/.docx/.pdf                  → 人工纪要
slides.pdf（material_type=会议PDF）           → 会议资料
```

隔离目录共保存18个源文件；资料包详情响应中不含 `relative_path`，也不含临时数据根路径。

## 6. 主要缺陷与建议

| 缺陷ID | 严重度 | 缺陷 | 建议 |
| --- | --- | --- | --- |
| BE-CORE-009 | 高 | 预检未验证文件签名、MIME、空文件和可读性 | 增加魔数／MIME／零字节检查；PDF、音视频和Office文件调用解析器做最小可读性探测 |
| BE-CORE-010 | 高 | 没有PDF页数、加密、扫描件／文本型识别 | 使用PDF解析适配器输出页数、加密状态、文本可提取性、OCR需求和错误原因；超过100页时阻止 |
| BE-CORE-011 | 高 | PDF例外只凭自由文本即可绕过配套规则 | 增加 `pdf_exception_confirmed_by/at/version`，仅产品规划负责人可确认；进入分析前校验 |
| BE-CORE-012 | 中 | 2GB上限统一套用所有材料，且提示只写“音频或录屏” | 按材料类型分别配置字节、页数、时长；错误消息返回实测值和处理建议 |
| BE-CORE-013 | 中 | 没有120分钟会议时长预检 | 使用FFprobe读取音视频时长；超限提示拆分，不自动截断 |

## 7. 待后续真实组件测试

- DOCX结构解析、PDF文本提取、OCR、加密PDF和100页边界。
- MP3／WAV／M4A／MP4真实编解码可读性、时长和音轨存在性。
- 2GB边界、磁盘空间不足、中断上传、上传重试。
- 删除、保留期限和受影响证据提示；当前没有对应材料生命周期API。
