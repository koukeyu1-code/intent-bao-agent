## 本轮修复范围

本轮实现“首层文件内容预检”，位于文件写入完成、材料记录落库之前：

- 零字节文件和空白文本拒绝；
- TXT、Markdown、SRT、VTT 要求内容非空且能以 UTF-8、带 BOM 的 UTF-16 或 GB18030 严格解码，含 NUL 的二进制内容拒绝；
- PDF 要求文件头存在 `%PDF-` 签名；
- DOCX 要求可作为 ZIP 打开，且 `[Content_Types].xml` 存在、可读取且非空；
- MP4、M4A 要求 ISO BMFF `ftyp` 容器签名；
- WAV 要求 `RIFF` 和 `WAVE` 签名；
- MP3 要求 `ID3` 或 MPEG 帧同步签名；
- 预检失败返回 `422`，已写入的目标文件立即删除，且不创建 `MaterialFile` 记录；
- 预检通过的材料 `parse_status` 明确记录为“预检通过”。

## 明确未实现、不得扩大解释的能力

本轮只做轻量魔数、容器与文本可读性检查，**没有**验证：

- PDF页数、加密状态、完整语法或每页可解析性；
- 音视频时长、编码格式、音轨／画面是否真实可解码；
- DOCX全部内部部件、宏、外部链接或压缩包安全扫描；
- 恶意文件查杀、内容安全和深度媒体探测。

因此“预检通过”只代表文件满足首层结构条件，不代表已完成业务解析或安全扫描。
100页PDF、120分钟会议等容量目标仍需后续接入专用解析器／`ffprobe` 后验证。
